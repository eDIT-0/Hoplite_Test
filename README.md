# Hoplite Local

Небольшой локальный веб-клиент к официальному API Hoplite. Работает на Windows без WSL, Docker и npm-зависимостей. Интерфейс — на русском языке.

## Запуск на Windows

1. Установите **Node.js 24 LTS** с https://nodejs.org (минимум — Node.js 22).
2. Скачайте этот проект и распакуйте в отдельную папку.
3. Скопируйте `.env.example` в `.env`. В Проводнике включите отображение расширений файлов, чтобы не получить `.env.txt`.
4. Создайте API-ключ организации в настройках Hoplite. Заполните локальный `.env`:

   ```dotenv
   HOPLITE_API_KEY=ваш_ключ
   PORT=3210
   ```

5. Дважды нажмите `start.cmd`. Откройте адрес, напечатанный в окне сервера (по умолчанию http://127.0.0.1:3210).
6. Выберите проект, откройте существующий диалог или отправьте первую задачу в новом.

Окно `start.cmd` должно оставаться открытым. Для остановки нажмите Ctrl+C. После изменения `.env` перезапустите сервер. Без ключа интерфейс показывает инструкцию подключения; баланс и диалоги не подменяются демонстрационными данными.

Альтернатива через PowerShell из папки проекта: `node server.mjs` или `npm start`. Установка пакетов не нужна. Порт можно изменить в `.env`, если 3210 занят.

## Права ключа

Ключ организации передаётся сервером как `X-Api-Key` только на `https://api.hoplite.sh`. Нужны права:

- `project:read` — проекты;
- `thread:read` — диалоги, сообщения, активный запуск;
- `thread:create` — новые задачи;
- `thread:update` — отправка сообщений;
- `thread:stop` — остановка запуска;
- `usage:read` — баланс и расходы;
- `modelKey:read` — каталог моделей.

Доступ к проектам и моделям ограничивается правами самого ключа. Сервисный ключ не наследует автоматически личные подписки создателя; доступ определяется настройками организации. Не используйте токены браузерной сессии и не присылайте ключ в переписку.

## Что умеет первая версия

- Переключать проекты, читать диалоги, загружать предыдущие сообщения.
- Создавать задачи и отправлять продолжения; выбирать модель следующего запуска.
- Показывать сохранённые ответы и сообщения статуса, обновляя данные каждые 5 секунд в активной вкладке. Это не поток отдельных токенов.
- Показывать модель диалога из `thread.modelId`, остаток и резерв кредитов, стоимость диалога. Модель диалога не является гарантией фактически использованной модели при fallback на стороне Hoplite.
- Останавливать конкретный активный запуск; открывать HTTP(S)-ссылки из ответов.
- Сохранять идентификатор неудачной отправки в памяти страницы для безопасного повтора с тем же текстом, моделью и диалогом. После перезагрузки страницы сначала проверьте историю, прежде чем повторять отправку.

Баланс и расходы обновляются отдельно: отсутствие права на биллинг не блокирует чат. История и ключ не сохраняются в localStorage. Сообщения отображаются как текст со ссылками; HTML из ответов не исполняется, сложный Markdown не форматируется.

**Границы версии:** подтверждения инструментов, вложения, управление проектами/репозиториями, биллинг и настройки аккаунта остаются в основном интерфейсе Hoplite. При статусе ожидания клиент напоминает об этом. Настройки automerge, доступа и автоматизации не переопределяются: новые диалоги наследуют настройки Hoplite. Отправка задач расходует обычные лимиты аккаунта.

## Безопасность

Сервер слушает только `127.0.0.1`, проверяет Host и Origin, не разрешает CORS и проксирует только небольшой список API-маршрутов. Ключ хранится в `.env` на компьютере и не передаётся странице. `.env` исключён из Git. Не публикуйте сервер через туннель, reverse proxy или общий доступ; локальные процессы на вашем компьютере считаются доверенными. Это не многопользовательский сервер.

## Проверки

```sh
npm test
npm run check
```

Серверные тесты используют поддельный upstream и не обращаются к аккаунту. Для ручной проверки: экран без ключа → выбор проекта → открытие диалога → выбор модели → отправка → новый ответ → остановка активного запуска. Проверяйте ошибки ключа, отсутствие права на баланс и переключение диалогов во время обновления.

Разработка и браузерная проверка выполнялись в Linux-окружении; `start.cmd` требует отдельной проверки на настоящей Windows. Полный сценарий с реальным аккаунтом требует локального API-ключа пользователя.

## Документация API

Контракт сверялся с официальной OpenAPI-схемой 9 ноября 2026 года:

- https://hoplite.sh/docs/api
- https://hoplite.sh/docs/openapi.json
- https://hoplite.sh/docs/api/getBillingSummary
- https://hoplite.sh/docs/api/appendThreadMessage

Используются `/api/projects`, `/api/threads`, `/api/threads/{id}`, `/api/threads/{id}/messages`, `/api/threads/{id}/active-run`, `/api/threads/{id}/stop`, `/api/threads/{id}/usage`, `/api/model-providers`, `/api/billing/summary`. Пагинация использует непрозрачный `nextCursor`; записи отправляются с `Idempotency-Key`.
